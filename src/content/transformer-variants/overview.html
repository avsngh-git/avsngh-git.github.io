The motivation

“More efficient” can mean several different things

Transformer variants often promise better quality, lower memory use, faster training, faster generation, or support for longer input. Those are separate goals, and improving one can make another worse.

A model can use fewer theoretical operations yet run slowly on a real GPU. It can predict better while storing twice as many parameters. It can also accept a long prompt without actually retrieving information from its distant beginning.

This project was built to measure those distinctions under one controlled system. Instead of asking for a single winner, it asks which architectural choice helps which resource, under which conditions, and at what cost.

The goals

Connect each architectural idea to measurable evidence

Ten decoder-only Transformer recipes are trained on the same language-modeling task. The shared data, token budget, optimizer schedule, training length, and primary hardware reduce accidental differences between recipes.

01

Compare prediction quality fairly

Train every recipe on the same number of tokens and repeat each main run with five random seeds.

02

Measure real system behavior

Record training, prompt processing, and generation speed instead of treating theoretical complexity as measured performance.

03

Test behavior beyond training length

Train at 1,024 tokens, then evaluate up to 4,096 tokens while separating prediction stability from distant retrieval.

04

Explain the trade-offs

Use internal probes, routing measurements, and explicit limitations to show what each result supports—and what it does not.

Terms used throughout

A small vocabulary before the variants

Token
A small unit of text processed by the model. A word may contain one or several tokens.
Attention
The operation that lets a token weigh information from earlier tokens when forming its next representation.
Context length
The number of tokens available to the model at once. This study trains at 1K and evaluates up to 4K.
Validation loss
A measure of next-token prediction error on held-out text. Lower is better.
Perplexity
Validation loss expressed as an effective number of plausible next-token choices. Lower is better.
Throughput
How many tokens an implementation processes each second on the measured hardware. Higher is better.
KV cache
A key-value cache that saves attention information from earlier tokens so generation does not recompute the whole prefix at every step.
Prefill and decode
Prefill processes the input prompt. Decode generates later tokens one at a time, often reusing the KV cache.
Position information
A rule that tells the model where tokens occur and how far apart they are.
Normalization
A step that rescales internal activations to make training more stable.
Feed-forward network
The per-token computation that transforms information after attention. It is sometimes shortened to FFN.
Mixture of experts
A larger set of feed-forward networks where a router selects only a few experts for each token. It is shortened to MoE.

The question to keep in mind

When a variant appears better, ask: better at prediction, training time, memory, prompt processing, generation, or length transfer? The next chapter introduces each recipe before any result is compared.
