The question

What actually changes when the Transformer mechanism changes?

“Transformer variant” can mean a positional encoding, an attention kernel, a sparsity pattern, a different feed-forward network, or several coordinated changes at once. Comparing names from unrelated papers is therefore not enough. I wanted to see what happens when the tokenizer, corpus, context length, optimization recipe, training budget, evaluation windows, and hardware are held as constant as the mechanism permits.

The result is not a single winning architecture. It is a map of trade-offs: conditional capacity can buy lower loss while harming latency; an explicit distance bias can extrapolate better than a stronger 1K model; and a better asymptotic complexity can lose to an optimized quadratic kernel on real GPU hardware.

Headline findings

Three results that changed how I think about “efficient” Transformers

01

MoE bought quality with conditional capacity—not free speed

Mechanism. The full mixture-of-experts model stores eight feed-forward experts and routes each token to the top two. That gives the router a larger conditional function family than one dense FFN.

yt= ∑e∈TopK(t) pte Ee(xt)

Evidence. Full MoE reached the lowest fixed-data validation loss, 3.4292 ± 0.0013, but its uncached short-generation throughput was only 42.87 tokens/s, compared with 454.55 tokens/s for Vanilla.

Caveat. MoE also violated the intended active-parameter parity: 68.8M parameters were active per token and 172.6M were stored. Expert dispatch produces smaller, irregular kernels, so sparse arithmetic did not become low latency at this scale.

02

Distance structure mattered more than 1K quality at 4K

Mechanism. ALiBI adds a head-specific linear penalty to attention logits. Because the term is defined by relative distance rather than a learned 1K lookup table, the same rule remains meaningful at 4K.

sijh = qi·kj dh −mh(i−j)

Evidence. ALiBI had the lowest 4K tail perplexity, 58.74 ± 1.10. SWA finished only 0.20 perplexity points behind, changed by essentially 1.000× from 1K to 4K, and reached 253K prefill tokens/s.

Caveat. SWA stayed stable because every query retained the same 256-token local window. That demonstrates clean local transfer and efficient prefill—not retrieval from tokens four thousand positions away.

03

Linear asymptotics met a fixed-state and hardware bottleneck

Mechanism. Causal linear attention replaces the explicit pairwise softmax matrix with recurrent prefix statistics. Sequence work can scale linearly in length, but every history is compressed into a fixed-size state.

Si=Si−1+φ(ki)viT zi=zi−1+φ(ki)

Evidence. The corrected linear model trained stably and reached a competitive 1K loss, but 4K tail perplexity rose to 1,311.78 ± 25.66; realized 4K prefill was only 34.7K tokens/s.

Caveat. This result is about the tested ELU+1 prefix recurrence, not every linear-attention design. The sequential, unfused path also competed against mature dense GPU kernels.

Architecture taxonomy

Ten recipes, grouped by the mechanism they change

A recipe is a buildable model configuration, not merely an attention class. The registry applies each recipe consistently so changes in position handling, normalization, feed-forward blocks, and cache behavior remain explicit.

Dense baselines

Vanilla

GPT-2-style decoder: learned absolute positions, LayerNorm, dense multi-head attention, and a dense FFN.

Hypothesis: a transparent reference point can remain competitive when its kernels and cache path are mature.

Expected cost: quadratic attention and no position support beyond the learned 1K table.

Modern

RoPE, RMSNorm, SwiGLU, and memory-efficient scaled dot-product attention.

Hypothesis: modern component choices improve optimization and quality without adding sparse capacity.

Expected cost: dense quadratic attention remains, and RoPE extrapolation is not guaranteed.

Position and KV efficiency

ALiBI

Replaces rotary position geometry with a head-specific linear distance penalty in the attention logits.

Hypothesis: an explicit relative-distance rule extrapolates beyond the training length.

Expected cost: full dense attention is still computed.

GQA

Eight query heads share two key/value heads.

Hypothesis: reduce KV parameters and cache memory while retaining diverse queries.

Expected cost: shared keys/values may reduce representational freedom; the current cache seam must support grouped heads.

Local and compressed attention

SWA

Every attention layer sees only the current token and its 255 predecessors.

Hypothesis: language modeling is sufficiently local to trade global edges for cheaper prefill.

Expected cost: information cannot cross more than one window per layer.

SWA interleaved

Alternates full global and 256-token local attention layers.

Hypothesis: periodic global mixing recovers long-range paths while preserving some locality.

Expected cost: global layers retain quadratic work and can reintroduce extrapolation sensitivity.

Causal linear

Uses an ELU+1 feature map and causal prefix-state recurrence with RoPE.

Hypothesis: remove the explicit attention matrix and make sequence work linear in length.

Expected cost: fixed-state compression loses token-level addressability; normalization is numerically sensitive.

Sparse feed-forward capacity

MoE

Eight FFN experts with top-2 routing in every Transformer block.

Hypothesis: increase conditional capacity without activating every stored parameter.

Expected cost: routing imbalance, extra memory, and irregular expert kernels.

MoE interleaved

Alternates dense and top-2 MoE feed-forward blocks.

Hypothesis: capture most sparse-capacity gains with less routing overhead.

Expected cost: still exceeds dense parameter parity and creates mixed execution paths.

MoE deep

Keeps the first half dense and places experts in deeper blocks.

Hypothesis: early layers learn general features while later experts specialize.

Expected cost: benefits depend on whether specialization actually emerges at this scale.

Experimental protocol

Hold the pipeline still, then change the mechanism

Every main recipe used the same GPT-style tokenizer, FineWeb-Edu source corpus, 1,024-token training sequences, optimizer family, effective token batch, and 15,000-step budget. FineWeb-Edu is a filtered web-text corpus; I streamed it, tokenized documents, inserted end-of-document separators, and wrote binary shards that the trainer memory-maps instead of loading the corpus into RAM.

Independent uncertainty units

I trained seeds 42, 137, and 2024. Error ranges use checkpoint-seed estimates, not batches or token positions treated as independent replicas.

Target-aligned long context

At 1K, 2K, and 4K, every model scores the same final 256 target tokens over eight fixed validation windows per checkpoint. Only available history changes.

Explicit unsupported states

A missing cache path, position range, or pairwise attention matrix is reported as unsupported. The evaluator does not emulate a result the model never used.

Training recipe

The objective and optimizer behind every comparison

All recipes are autoregressive language models. Given tokens x1…xT, the model predicts each next token from its causal prefix. The dense-model objective is mean next-token cross-entropy:

LCE= −1T ∑t=1T logpθ (xt+1 |x≤t)

Lower cross-entropy means the model assigns more probability to held-out next tokens. Perplexity is its exponential, so a loss difference is multiplicative in average token uncertainty rather than merely a cosmetic score change.

MoE recipes add two router regularizers to cross-entropy: a load-balancing term that discourages expert collapse and a z-loss that controls router-logit scale.

LMoE= LCE+ αE∑e=1E fePe+ βmean(logsumexp(r)2)
OptimizerAdamW; β₁ = 0.9, β₂ = 0.95, weight decay = 0.1
Learning rate3×10−4 peak, 3×10−5 floor
Schedule5M-token linear warmup, then cosine decay
Batch8 sequences × 8 accumulation steps × 1,024 tokens = 65,536 tokens/update
Precisionbfloat16 autocast; numerically sensitive reductions remain float32 where required
StabilityGlobal gradient norm clipped at 1.0; non-finite updates abort before optimizer mutation
Budget15,000 optimizer steps = 983,040,000 tokens per main run
MoE termsLoad balance α = 0.01; router z-loss β = 0.001

How I separate an architecture result from a systems result

Quality is a distribution, not one checkpoint

The fixed-data headline uses the mean and standard deviation across three independently trained seeds at the common token budget. That makes the checkpoint—not a batch, window, or individual token—the replication unit. A difference larger than the observed seed spread is evidence that the recipe changed optimization behavior under this setup. It is still not a universal ranking: scaling the model, changing the corpus, or retuning one architecture could change the order.

Parameter counts answer two different questions

Total parameters determine storage and memory pressure; active parameters approximate how much learned capacity participates in one token's forward pass. Dense models make those numbers equal. Top-2 MoE does not: two experts execute per token, while all eight must remain resident. I therefore show both counts and treat the failed active-parameter parity as a limitation. Without that distinction, calling the MoE result “more efficient” would hide the extra function capacity that likely produced its lower loss.

Complexity predicts scaling; measurement reveals the regime

Big-O notation describes what happens as sequence length grows, after constants and hardware effects are ignored. These experiments live in a finite regime on one NVIDIA L4-24Q. Wall-clock and throughput therefore include kernel fusion, tensor shapes, memory traffic, expert dispatch, synchronization, and cache support. The linear recurrence has the better asymptotic attention bound, but the tested implementation never reaches the length where that advantage outweighs its serial unfused work. I report that as an implementation-aware result, not a contradiction of complexity theory.

Controlled results

Quality is only meaningful beside the budget that produced it

Long-context extrapolation: quality leaders changed after 1K

Throughput: generation and prefill are different workloads

Autoregressive generation repeatedly advances one token; prefill processes a complete prompt in parallel. I keep them separate because a model can be good at one and poor at the other, and cache support changes the execution path.

Inside the models

Loss says whether a model predicts; probes suggest how its layers organize

I used stable rank to summarize how broadly a layer spreads activation energy across representation directions. Linear CKA measures similarity between layer representations: high adjacent-layer CKA means neighboring blocks transform the residual stream more conservatively; lower values indicate a larger geometric change. These are diagnostics, not quality scores.

Attention-pattern explorer

Memory-efficient kernels avoid storing the full probability matrix. For visualization, the exporter reconstructs the exact pre-dropout softmax probabilities from each selected layer’s normalized input, including RoPE, ALiBI bias, GQA head sharing, causal masks, and SWA windows.

Engineering design choices

The comparison is a system, not a notebook

Registry-driven construction

Problem: variant-specific conditionals scattered through the trainer would make controls hard to audit.

Choice: recipes own their model class, attention/FFN overrides, and per-layer rules behind one build interface.

Trade-off: the registry must expose every meaningful deviation; hidden defaults would undermine the experiment.

Streaming data preparation

Problem: a billion-token corpus should not require loading raw documents or token arrays into RAM.

Choice: stream, filter, tokenize, and write checksummed uint16 shards with a manifest; memory-map only the active shard.

Trade-off: sequential shards simplify throughput and provenance, while full example-level shuffling is intentionally avoided.

Three fairness axes

Problem: equal tokens, equal elapsed time, and equal FLOPs are different scientific questions.

Choice: report all three rather than selecting the axis that favors one architecture.

Trade-off: FLOPs are modeled rather than hardware time, while wall-clock includes kernel maturity and implementation quality.

Checkpoint-level uncertainty

Problem: thousands of token losses are correlated observations from the same trained model.

Choice: use three independently trained checkpoints as the uncertainty units and fixed windows for paired context comparisons.

Trade-off: three seeds give honest but still limited uncertainty estimates.

Fault-tolerant recovery

Problem: long GPU runs can lose progress or resume from subtly corrupted state.

Choice: asynchronous atomic saves, SHA-256 verification, ring rotation, health monitoring, and restoration of model, optimizer, RNG, and loader cursors.

Trade-off: CPU snapshots and integrity metadata add complexity, but failures become explicit and testable.

Frontend-agnostic publication

Problem: a server-bound dashboard is fragile as a portfolio artifact.

Choice: export strict JSON and PNGs from the experiment repo, freeze them at a commit, and render with small local Jekyll assets.

Trade-off: publication is a deliberate snapshot; new experiments require an explicit re-export.

Interpretation boundaries

What these experiments do not establish

  • Parameter parity failed for MoE. Its quality advantage cannot be attributed to routing alone because active and stored capacity increased.
  • Some historical time/FLOP histories lack independent error ranges. Copied seed histories cannot support artificial uncertainty bars.
  • Generation timing uses one representative checkpoint per recipe. It is a hardware diagnostic, not a population estimate over training seeds.
  • Long-context tests are extrapolation. Models trained at 1,024 tokens were evaluated at up to 4,096; this is not equivalent to long-context training.
  • SWA stability is local. A fixed 256-token window can remain stable at a 4K container without retrieving from the distant prefix.
  • Linear attention is a different operator. It has no conventional softmax heatmap, and this implementation does not represent all linear-attention families.
  • Hardware conclusions are scoped. Measurements come from an NVIDIA L4-24Q and depend on these kernels, batch sizes, and cache implementations.
